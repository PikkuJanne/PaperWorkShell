# Removal export authority and reports

PWS-0607 composes a separate, private candidate operation and a final publication
gate. [Removal intent](redaction-intent-review.md) remains unapplied in the case.
Ordinary PDF, searchable, flattened, target-size, package, ZIP and prepared-output
paths retain their existing active-mark blockers. Removing marks from a plan to
reuse an ordinary export path is prohibited.

## Exact authority chain

The private `pdf.redaction_export_private` worker scope receives one retained
original handle and an authenticated reconstruction request. Within the isolated
worker it inventories affected source stream/image fingerprints, reconstructs
masked pixels, sanitizes the derivative, and invokes the
[multi-method verifier](redaction-verification.md) against the exact reconstructed
reference. Only internal identifiers, numeric facts, digests and closed reports
cross the boundary. Source parsing never moves into the GUI.

The returned chain binds the original source and reviewed intent, reconstruction
request and output, sanitizer input and output, canonical verification request,
method results, operation and output identities. The broker authenticates the
actual output buffer and issues one opaque, single-use candidate. A record or an
arbitrary stream cannot replace this broker-owned authority. Reuse, a consumed or
closed candidate, changed evidence, mismatched result correlation, a different
broker and the viewer-resave verification profile are rejected.

The current composed profile has **one affected PDF page**. Whole-case review
rejects multiple active pages, active overlays, and unsupported cleanup intent;
it never silently drops them. Crop and quarter-turn intent use the accepted
reconstruction coordinates. Signature markers require the existing unsigned
derivative confirmation and must match the worker's observed marker state.
Affected content, image and Form streams require the proved bounded unfiltered
or single-Flate profile. JPEG/DCT, unsupported filters and decode parameters fail
closed even when a reader could otherwise display that source.
This private profile does not regenerate OCR or promise searchable output.
Independent OCR and viewer methods are therefore unknown for its exact new bytes.
The broker rejects any invented external-method pass. Accepted historical reader
and OCR evidence remains bound to its original artifacts.

## Final publication and retry

`RedactionExportService` requires exact reviewed state and repeats current
manifest/CAS, source-integrity, report-chain and buffer checks before commit.
Every required method must pass; one failed, unknown, malformed, omitted or stale
result blocks publication. All-pass method evidence is still insufficient for
independent release approval. The build-time permanent-removal switch remains
false pending PWS-0608. There is no caller approval boolean, environment setting,
UI override, or report field that enables it.

The final destination port uses the existing authenticated no-replace writer.
It stages exact bounded bytes, checks their size/digest, and reopens the final
name. A retry begins a fresh operation against current intent; it cannot overwrite
a previous verified output. An uncertain publication remains uncertain and does
not offer an automatic retry. Cleanup failure after confirmed commit preserves
the committed fact. Source, manifest and candidate context managers cannot
suppress an exception to fabricate success.

The publication branch is exercised with synthetic trusted ports and a test-only
simulated approved build. This is not a release approval, native public-export
claim, or permission to enable the feature. The actual private worker provides
no independent OCR/viewer testimony, so its candidate remains blocked even in
that simulation.

## User and technical reports

The versioned `RedactionExportReport` separates blocked, not committed, committed
and uncertain outcomes. Its user view states affected internal page IDs, every
required method with pass/fail/unknown and a closed code, and unsigned derivative
status. It never promotes saved marks. Missing evidence is displayed as unknown;
an unapplied or failed result is never called redacted.

The audit projection contains only internal IDs, versions, counts, status and
closed method/result codes. It excludes document/OCR text, filenames, paths,
metadata values, probes, signature images and correlation digests. The private
record retains digests for internal authentication; it is not a routine log or a
support export. Creating a diagnostic bundle remains the separate, opt-in
previewable PWS-0805 workflow.

The native result dialog has a read-only report, visible and announced status,
keyboard navigation, recovery focus and Review marks/Retry/Close actions. Retry
is unavailable while release approval is pending or the destination is uncertain.
An existing export blocked by unapplied intent presents the actual current marked
page IDs and seven unknown methods. Package review releases its retained lease
before opening the report or mark editor. No invented check is shown as complete.

worker, bounded source/reference/candidate/resave storage, bounded source graph
traversal and output transfer. Cancellation, deadline, low-storage, malformed
result, candidate mutation and cleanup paths fail closed. Originals remain
immutable, and intermediate artifacts are scoped to the private worker.

sealed capability backed by its retained native directory pin. Fresh read-only

verifier callers still authenticate every ancestor. Parent-folder permissions
are not broadened; unavailable ancestor metadata produces a closed access-failure
code rather than an invented verification pass.

this work supplies no hardware certification, portal acceptance, digital-signature
